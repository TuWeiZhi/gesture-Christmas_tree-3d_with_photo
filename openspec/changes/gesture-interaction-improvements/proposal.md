# 手势交互改进提案

## 用户原始需求

1. **候选照片标识不明显**，希望通过呼吸效果或其他方法增强视觉反馈
2. **旋转交互问题**：握拳手势超出摄像头范围后再回来，画面会跳回初始位置，希望能从当前角度继续旋转
3. **手势替换**：将捏合手势换成食指中指的"比耶"手势

## 问题分析

### 1. 候选照片标识问题
**现状**：
- 仅通过固定的边框发光（emissiveIntensity: 0.5）和微小缩放（1.15x）标识
- 在动态 3D 场景中，静态对比不够醒目

**根因**：缺乏动态视觉反馈

### 2. 旋转跳回问题
**现状**：
```javascript
const targetRotY = STATE.hand.x * Math.PI * 0.9;
STATE.rotation.y += (targetRotY - STATE.rotation.y) * 3.0 * dt;
```

**根因**：旋转是"绝对位置映射"，手的 x 坐标直接映射到旋转角度，手离开再回来会被拉回固定角度

### 3. 手势替换需求
**现状**：使用拇指-食指捏合（pinchRatio < 0.35）触发 FOCUS
**需求**：改为食指+中指伸直的"比耶"手势

## 协作研究成果

### Gemini 前端方案
1. **呼吸光晕**：Math.sin() 动态调制 emissiveIntensity (0.4-1.0) 和 scale (1.15-1.2)
2. **增量旋转**：记录 lastHandX，计算 deltaX 累加到 rotation.y
3. **比耶检测**：食指/中指距离 > handSize * 0.8，无名指/小指 < handSize * 1.2

### Codex 技术审查
**严重问题**：
- 增量旋转不能放在 `animate()` 里（渲染帧 vs 摄像头帧频率不同）
- `handSize < 0.02` 早退不清状态，会产生幽灵旋转
- 高亮缩放必须基于 `userData.baseScale` 而非 `Particle.baseScale`
- Bloom 阈值 0.95，emissiveIntensity 拉到 1.0 会触发泛光

**优化建议**：
- 呼吸效果通过 `targetScale` 写入，让现有插值管线处理
- 增量旋转在 `processGestures()` 中按摄像头帧计算
- 添加死区和最大值限制防止抖动
- 比耶手势判定优先级高于粗分类

## 实施方案

### 1. 呼吸光晕效果
- 发光强度：0.25-0.75（避免触发 Bloom）
- 缩放范围：1.15-1.22
- 脉冲速度：4.5 rad/s
- 边框缓存：`userData.borderMesh`

### 2. 增量式旋转
- 灵敏度：π * 1.35
- 死区：0.01
- 最大值：0.12
- 重置时机：手消失、进入 FOCUS、handSize 无效

### 3. 比耶手势
- 食指距离：> handSize * 1.55
- 中指距离：> handSize * 1.60
- 无名指距离：< handSize * 1.45
- 小指距离：< handSize * 1.35
- 两指间距：> handSize * 0.35
- Debounce：2 帧

## 预期效果

1. **视觉反馈增强**：候选照片有明显的金色光晕脉动，吸引用户注意
2. **旋转体验优化**：手势可以累积旋转角度，实现单向连续旋转
3. **手势更直观**：比耶手势比捏合更容易识别和执行
